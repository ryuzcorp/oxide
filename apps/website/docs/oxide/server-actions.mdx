Write the function once in `*.server.ts`. Import it from the browser. Oxide turns that import into Effect RPC (HTTP or WebSocket). The module body, database clients, and unmarked helpers stay on the server — they never enter the client graph.

## Create an action

Name the file `*.server.ts` (or `.tsx` / `.js` / `.jsx`). Wrap every remotely callable export in `action()`:

```ts twoslash src/greet.server.ts
import { action } from "oxidejs";

export const greet = action(async (name: string) => {
  return { message: `hello, ${name}` };
});
```

Call it from the client with the **same import path**. Types flow from the server module; the runtime call is RPC:

```ts twoslash src/client.ts
// @filename: greet.server.ts
import { action } from "oxidejs";
export const greet = action(async (name: string) => {
  return { message: `hello, ${name}` };
});
// ---cut---
// @filename: client.ts
import { greet } from "./greet.server";

const { message } = await greet("Ryuz");
```

By default the stub POSTs `/__oxide/action` as newline-delimited JSON-RPC (`application/json-rpc`). The method name is `<file>.<export>` — here `greet.greet`. A [`batch()`](#batch-calls) call posts one JSON-RPC 2.0 batch array instead.

## Only `action()` is public

Exports that are not wrapped stay server-local. Secrets and helpers are not callable over the wire:

```ts twoslash src/users.server.ts
import { action } from "oxidejs";

declare const API_KEY: string;

const normalize = (name: string) => name.trim();

export const saveName = action(async (name: string) => {
  // API_KEY and normalize never appear in the client stub
  void API_KEY;
  return normalize(name);
});

export const internalLabel = "not an RPC method";
```

`action()` does not validate input or authorize users by itself. Treat arguments as untrusted — use [`withSchema`](#validate-input-with-effect-schema) and check the current user before reading or changing private data.

## Call shape on the client

Unary actions return a Promise and expose helpers for UI wiring:

| Call | What it does |
| --- | --- |
| `await greet(name)` | Run the action (always invokes RPC on the client) |
| `greet.set(...args)` | Same as calling with args; also writes the atom |
| `greet.bind(...args)` / `greet.with(...args)` | Return an event handler that invokes the action |
| `greet.result` | Read the last `AsyncResult` from the client atom |

```ts twoslash src/bind.ts
// @filename: tasks.server.ts
import { action } from "oxidejs";
export const toggle = action(async (id: string) => ({
  id,
  done: true,
}));
// ---cut---
// @filename: bind.ts
import { toggle } from "./tasks.server";

document.querySelector("button")!.onclick = toggle.bind("task-1");
```

Stream actions do not support `bind` / `with`. On the client they resolve to an async generator — `await` first, then `for await`.

## Batch calls

`batch()` collects calls made in the same tick and sends them as one JSON-RPC 2.0 batch — a single POST, one round trip:

```ts twoslash src/batch.ts
// @filename: tasks.server.ts
import { action } from "oxidejs";
export const ping = action(async () => "pong");
export const task = action(async (id: string) => ({ id }));
// ---cut---
// @filename: batch.ts
import { batch } from "oxidejs";
import { ping, task } from "./tasks.server";

const [pong, first] = await batch(ping, task("a"));
```

Items are pending calls (`task("a")`), thunks that start one (`() => task(id)`), or a bare handle for a zero-arg action (`ping`). `batch([ping, task("a")])` is the same call. Types flow per item, so `first` is `{ id: string }`.

| Detail | Behavior |
| --- | --- |
| Wire | one POST to `/__oxide/action` with a JSON-RPC 2.0 batch array |
| Result | values in call order; a failing call rejects the promise |
| Same tick | calls must be created in the `batch()` tick — an earlier call already went out |
| Transport | HTTP only: `transport: "ws"` still sends one message per call |
| Server / SSR | the same calls run locally, in parallel |
| Stream actions | not batchable — iterate `ticks()` directly |
| `{ signal }` | an aborted call is dropped from the batch; the rest still post |
| `{ idempotencyKey }` | carried as a per-frame header, so `useIdempotencyKey()` works |

JSON-RPC 2.0 answers a batch as one response set, so the slowest call in a batch sets the latency for all of them. Batch calls that belong together instead of pushing an unbounded list through one request.

## Validate input with Effect Schema

Invalid payloads become JSON-RPC **Invalid params** (`-32602`) over `/__oxide/action`, with the Schema message when Effect surfaces it — not a silent bad row in your database:

```ts twoslash src/add.server.ts
import { Schema } from "effect";
import { action, withSchema } from "oxidejs";

const AddTask = Schema.Struct({
  text: Schema.String,
});

export const add = action(
  withSchema(AddTask, async (payload) => {
    // payload.text is string — Encoded was checked on the wire
    return { id: crypto.randomUUID(), text: payload.text };
  })
);
```

`withSchema` is sugar for `action(handler, { payload })` plus a local decode for direct server calls. `await add(payload)` is typed as the handler's data — there is no Effect union to narrow. Calling the `withSchema` function directly with an invalid payload throws `SchemaDecodeError` before the handler runs; through `action()` that is a rejected promise. Over RPC the payload is decoded before the handler runs, so an invalid payload is JSON-RPC invalid params (`-32602`). Prefer one Struct payload over many positional args — it matches Effect Rpc and stays easy to evolve. Schemas that need decoding services are not supported yet.

### Typed Fail on the wire

Pass an `error` schema (`Schema.TaggedError`) so Fail values encode for the client instead of scrubbing to a generic Internal error:

```ts twoslash src/get-task.server.ts
import { Effect, Schema } from "effect";
import { action } from "oxidejs";

class NotFound extends Schema.TaggedError<NotFound>()("NotFound", {
  id: Schema.String,
}) {}

export const getTask = action(
  (id: string) =>
    Effect.gen(function* () {
      return yield* Effect.fail(new NotFound({ id }));
    }),
  { error: NotFound }
);
```

Clients see application error `-32000` with the tag/message. Returning an `Error` as a value does not promote it over RPC — use `Effect.fail` or throw the tagged error.

A rejected client call is an `Error` instance, so `error.message`, `error._tag`, `error.code` and `String(error)` all work. A declared tagged error keeps its `_tag` and decoded fields, and rejects as an instance of the class when its schema reached the client (see [Schemas on the client](#schemas-on-the-client)); invalid params become `SchemaDecodeError` (`-32602`). Plain thrown `Error`s stay masked as `Internal error` (`-32603`) — to surface a user-facing message, call `fail(message)`, which throws `ActionFailure`:

```ts twoslash src/save.server.ts
import { action, fail } from "oxidejs";

export const save = action(async () => {
  fail("Not allowed");
});
```

The generated action always unions `ActionFailure` into its error schema, so `fail()` needs no `error` option and still works when you declare your own `Schema.TaggedError` `error` for a richer typed failure.

### Schemas on the client

The generated client group uses your schemas only when they live outside `*.server.ts`. Import them from a plain module:

```ts twoslash src/tasks.server.ts
// @filename: schemas.ts
import { Schema } from "effect";

export const AddTask = Schema.Struct({ text: Schema.String });

export class NotFound extends Schema.TaggedError<NotFound>()(
  "NotFound",
  {
    id: Schema.String,
  }
) {}
// ---cut---
// @filename: tasks.server.ts
import { action, withSchema } from "oxidejs";
import { AddTask, NotFound } from "./schemas";

export const add = action(
  withSchema(AddTask, async ({ text }) => ({ id: "1", text })),
  { error: NotFound }
);
```

The client then validates the Encoded payload before sending, decodes the response with `success`, and rebuilds a declared tagged error as an instance of your class:

| Where the schema is | Client behavior |
| --- | --- |
| Imported from a plain module | an invalid payload rejects with `SchemaDecodeError` (`-32602`) and no request goes out; a `success` schema decodes the wire value (`Schema.Date` arrives as a `Date`); a declared `error` rejects as `instanceof NotFound` with its fields and `code: -32000` |
| Inline, locally declared, or in another `*.server.ts` | `Schema.Unknown` in that slot: no payload check, no success decode, and a declared error arrives as an `ActionError` carrying `_tag`, `code` and the decoded fields |

The client bundle never imports a `*.server.ts` file, so the shared module must not import one either. `ActionFailure` and `SchemaDecodeError` keep working either way.

### Effect handlers and services

Prefer Effect handlers (`Effect.gen`, Schema-stamped `payload` / `error`, services). `action()` also accepts Promise, `async function*`, and (with `{ stream: true }` or a returned `Stream`) Effect `Stream`. Yield `OxideRequest` / `OxideCtx` for the same data as `useRequest()` / `useCtx()`:

```ts twoslash src/who-effect.server.ts
import { Effect } from "effect";
import { action, OxideRequest } from "oxidejs";

export const who = action(() =>
  Effect.gen(function* () {
    const req = yield* OxideRequest;
    return req.headers.get("x-user");
  })
);
```

Handlers run under an `oxidejs.action` span annotated with `rpc.method`. Provide `oxideRuntimeLayer()` (or your own Logger / Tracer Layer) at the host if you want spans collected.

## Authorization without leaking `user` to the client

Keep auth on the server. The client calls `profile()` with no user argument — your wrapper loads the session and passes `user` only into the handler:

```ts twoslash src/profile.server.ts
// @filename: db.ts
export type User = { id: string; role: "user" | "admin" };
export declare const db: {
  users: { findByToken(token: string): Promise<User | undefined> };
  profiles: {
    find(userId: string): Promise<{ name: string } | undefined>;
    update(userId: string, input: { name: string }): Promise<void>;
  };
};
// ---cut---
// @filename: profile.server.ts
import { Effect, Schema } from "effect";
import { action, OxideRequest } from "oxidejs";
import { db, type User } from "./db";

class UnauthorizedError extends Schema.TaggedError<UnauthorizedError>()(
  "UnauthorizedError",
  {
    message: Schema.String,
  }
) {}

const requireUser = Effect.gen(function* () {
  const request = yield* OxideRequest;
  const authorization = request.headers.get("authorization");
  if (!authorization) {
    return yield* Effect.fail(
      new UnauthorizedError({ message: "Unauthorized" })
    );
  }
  const user = yield* Effect.promise(() =>
    db.users.findByToken(authorization)
  );
  if (!user) {
    return yield* Effect.fail(
      new UnauthorizedError({ message: "Unauthorized" })
    );
  }
  return user;
});

function withUser<Args extends unknown[], A, E>(
  handler: (user: User, ...args: Args) => Effect.Effect<A, E>
) {
  return (...args: Args) =>
    Effect.gen(function* () {
      const user = yield* requireUser;
      return yield* handler(user, ...args);
    });
}

export const profile = action(
  withUser((user) => Effect.promise(() => db.profiles.find(user.id))),
  { error: UnauthorizedError }
);

export const update = action(
  withUser((user, name: string) =>
    Effect.promise(() => db.profiles.update(user.id, { name }))
  ),
  { error: UnauthorizedError }
);
```

Client input stays typed (`name: string` on `update`). Session and DB access stay off the wire. Do not return tokens or credentials from an action.

## Stream values

Wrap an `async function*` in `action()` to stream over Effect RPC as **newline-delimited JSON-RPC** (not SSE). Frames scrub as they flush — clients see early chunks without waiting for the generator to finish:

```ts twoslash src/ticks.server.ts
import { action } from "oxidejs";

export const ticks = action(async function* (count: number) {
  for (let i = 0; i < count; i++) yield i;
});
```

```ts twoslash src/client-stream.ts
// @filename: ticks.server.ts
import { action } from "oxidejs";
export const ticks = action(async function* (count: number) {
  for (let i = 0; i < count; i++) yield i;
});
// ---cut---
// @filename: client-stream.ts
import { ticks } from "./ticks.server";

for await (const value of await ticks(3)) {
  console.log(value);
}
```

On the server, `ticks(3)` is an async generator. On the client, `await` the call first, then iterate. Breaking the loop (or `return()`) cleans up the server generator. Over HTTP, Oxide does not reconnect a dropped stream. With `transport: "ws"`, transient closes retry; abort via `{ signal }` does not.

## Live queries

Push successive snapshots for one topic: subscribe is the query, mutate/publish is the write. The hub is isolate-local Effect PubSub — your database remains the source of truth:

```ts twoslash src/tasks.server.ts
import { action, liveQuery } from "oxidejs";

type Task = { id: string; text: string };

const tasks = liveQuery<Task[]>({ topic: "tasks" });

export const list = action(
  tasks.subscribe(async () => {
    // Capture request-scoped handles before the first await on Workers.
    await tasks.mutate(async () => [] as Task[]);
  })
);

export const add = action(async (text: string) => {
  await tasks.mutate(async () => [{ id: crypto.randomUUID(), text }]);
});
```

Under SSR, `*.server.ts` keeps the real generator (no WebSocket) so you can take the first snapshot for first paint. On the client, the same import resumes over `actions: "ws"`. Transient socket errors retry inside the stream client.

## Cancel a call

Pass `{ signal }` and optional `{ idempotencyKey }` as the final `CallOptions` argument. Inside the action, read the non-optional signal from `useRequest().signal`:

```ts twoslash src/abort.ts
// @filename: test.server.ts
import { action, useRequest } from "oxidejs";

export const ping = action(async () => "pong" as const);
export const ticks = action(async function* (count: number) {
  const { signal } = useRequest();
  for (let i = 0; i < count && !signal.aborted; i++) yield i;
});
// ---cut---
// @filename: abort.ts
import { ping, ticks } from "./test.server";

const controller = new AbortController();
const stream = await ticks(10, { signal: controller.signal });
await ping({ signal: controller.signal });
controller.abort();
void stream;
```

`idempotencyKey` is sent as `x-oxide-idempotency-key` and available via `useIdempotencyKey()`. When the mutation queue replays, claim the key before writing. On D1 do not use paranorm `once()`: it claims with `INSERT OR IGNORE` and then reads `SELECT changes()` in a follow-up statement, but D1 runs each statement in its own implicit transaction and does not carry `changes()` across them — the follow-up reports 0, so the write never runs. Use a single `INSERT … ON CONFLICT DO NOTHING RETURNING` — it returns no row when the key already exists:

```ts
const claim = (key: string) =>
  Effect.gen(function* () {
    const sql = yield* SqlClient;
    const rows = yield* sql<{ key: string }>`
      INSERT INTO paranorm_idempotency (key) VALUES (${key})
      ON CONFLICT DO NOTHING
      RETURNING key
    `;
    return rows.length > 0;
  });

export const add = action((text: string) =>
  Effect.gen(function* () {
    const key = useIdempotencyKey();
    if (key && !(yield* claim(key))) {
      return;
    }
    // ...write
  })
);
```

## Mutation queue (client)

Optional write queue for `transport: "ws"`. Transient socket failures enqueue; `flush` (and `online`) drain FIFO. The same `action()` types — no second client API:

```ts twoslash src/queue.ts
// @filename: tasks.server.ts
import { action } from "oxidejs";
export const add = action(async (text: string) => ({ id: "1", text }));
// ---cut---
// @filename: queue.ts
import { createMutationQueue } from "oxidejs/mutation-queue";
import { add } from "./tasks.server";

const queue = createMutationQueue();
const addQueued = queue.wrap(add, {
  idempotencyKey: (text) => `add:${text}`,
});

await addQueued("Buy milk");
```

Optimistic UI is app-owned — listen with `queue.subscribe`. HTTP apps can ignore this module.

### Durable storage

Add `storage` to keep a failed write across a reload. `indexedDbStorage()` is a browser adapter with no dependencies; implement `load` / `put` / `delete` for anything else:

```ts twoslash src/queue-storage.ts
// @filename: tasks.server.ts
import { action } from "oxidejs";
export const add = action(async (text: string) => ({ id: "1", text }));
// ---cut---
// @filename: queue-storage.ts
import {
  createMutationQueue,
  indexedDbStorage,
} from "oxidejs/mutation-queue";
import { add } from "./tasks.server";

const queue = createMutationQueue({ storage: indexedDbStorage() });
const addQueued = queue.wrap(add, {
  key: "tasks.add", // "<file>.<fn>": how a restored write finds its action
  idempotencyKey: (text) => `add:${text}`,
});

const surface = (message: string) => {
  // your toast / telemetry
};

queue.subscribe((event) => {
  if (event.type === "discard" && event.item) {
    surface(`dropped ${event.item.id}`);
  }
});

await addQueued("Buy milk");
```

With storage, `wrap` needs `key`, and args must survive `structuredClone`; a call that cannot be persisted rejects at enqueue with a clear error. Restored writes replay in FIFO order once their action is wrapped, keeping the same `idempotencyKey` so server-side dedupe still applies. Nothing awaits a restored write, so its outcome arrives as an event: `restore`, `success`, or `discard` (removed after a permanent failure). `await queue.ready` waits for the load. `indexedDbStorage()` throws where IndexedDB is missing (SSR, Node); a store that is present but unwritable (private mode) emits `error` and the queue keeps working in memory. `storage: "memory"` (the default) changes nothing.

## Request context

### `useRequest()`

The inbound `Request` in actions, SSR, and frame renders:

```ts twoslash src/who.server.ts
import { action, useRequest } from "oxidejs";

export const who = action(async () => {
  return useRequest().headers.get("x-user");
});
```

### `useCtx()`

`{ req }` plus fields your middleware stamped:

```ts twoslash src/me.server.ts
import { action, useCtx } from "oxidejs";

export const me = action(async () => {
  return useCtx<{ req: Request; user?: string }>().user;
});
```

Stamp host bindings (D1, KV, …) before actions and WebSocket upgrade:

```ts twoslash src/middleware/db.ts
import { stampRequestContext } from "oxidejs";

declare class D1Database {}

export default function db(
  request: Request,
  { env }: { env?: { DB?: D1Database } }
) {
  if (env?.DB) {
    stampRequestContext(request, { db: env.DB });
  }
}
```

Read them with `useCtx().db` (or a small `useDb()` helper).

### `useEnv()` and `useFetchCtx()`

On [`preset: "worker"`](/oxide/configuration#preset), these are the Worker `env` and `ctx` from `fetch(request, env, ctx)`. On Node they are `undefined` unless you pass [`env`](/oxide/configuration#env):

```ts twoslash src/env.server.ts
import { action, useEnv, useFetchCtx } from "oxidejs";

type Env = { API_URL: string };

export const hasApi = action(async () => {
  useFetchCtx()?.waitUntil?.(Promise.resolve(null));
  return Boolean(useEnv<Env>()?.API_URL);
});
```

Anything an action returns is sent to the caller — do not return secrets.

## Transport and path

HTTP is the default. Endpoint `/__oxide/action`, same-origin protection on:

```ts twoslash
import oxide from "oxidejs/vite";

oxide({
  actions: {
    path: "/rpc",
    sameOrigin: true,
  },
});
```

Use `transport: "ws"` for live queries and the mutation queue. Node/`fetch` needs `crossws`; [`preset: "worker"`](/oxide/configuration#preset) uses `WebSocketPair`:

```ts twoslash
import oxide from "oxidejs/vite";

oxide({
  actions: { transport: "ws", path: "/rpc" },
});
```

Set `actions.openrpc: true` to serve `GET /__oxide/openrpc` — an [OpenRPC](https://spec.open-rpc.org/) 1.3 document for `action()` handlers only (Effect Schema → JSON Schema; workflows, queues, and schedules are omitted). OpenRPC is HTTP-only and stays off when `transport` is `"ws"`. See [`actions`](/oxide/configuration#actions).

Set `sameOrigin: false` only when you accept another origin and own CORS, CSRF, and authentication. For static client headers, see [`actionHeaders`](/oxide/configuration#actionheaders) — never put a private secret there.
