Pass options to `oxide()` in your Vite or Rsbuild config. Start with `oxide()` — add options when the defaults are wrong for your app.

| Option | Default | What it controls |
| --- | --- | --- |
| [`preset`](#preset) | `"fetch"` | Node-style fetch server or Workers output |
| [`workerEntry`](#workerentry) | `src/server.ts` | Server entry file (optional when default is missing) |
| [`outDir`](#outdir) | `dist` | Build output folder |
| [`clientDir`](#clientdir) | `client` | Client folder inside `outDir` |
| [`wrangler.name`](#wrangler) | required if `emitConfig` | Worker name |
| [`wrangler.compatibility_date`](#wrangler) | required if `emitConfig` | Worker compatibility date |
| [`wrangler.compatibility_flags`](#wrangler) | - | Optional worker flags |
| [`wrangler.account_id`](#wrangler) | - | Optional Cloudflare account id |
| [`wrangler.workers_dev`](#wrangler) | - | Optional Cloudflare `*.workers.dev` |
| [`wrangler.routes`](#wrangler) | - | Optional Cloudflare routes |
| [`wrangler.kv_namespaces`](#wrangler) | - | Optional KV namespaces |
| [`wrangler.durable_objects`](#wrangler) | - | Optional Durable Object config |
| [`wrangler.migrations`](#wrangler) | - | Optional migrations |
| [`wrangler.services`](#wrangler) | - | Optional service bindings |
| [`wrangler.vars`](#wrangler) | - | Optional variables |
| [`emitConfig`](#emitconfig) | `true` on `worker` | Whether to write `wrangler.jsonc` |
| [`actions`](#actions) | `"http"` | Action transport, endpoint path, and same-origin protection |
| [`actionHeaders`](#actionheaders) | - | Public static headers added by the browser action client |
| [`middleware`](#middleware) | `[]` | Production request middleware, in order |
| [`imports`](#imports) | `[]` | Side-effect modules loaded at server startup |
| [`bodyLimit`](#bodylimit) | `1048576` | Max Node request body size (413 when exceeded) |
| [`notFound`](#notfound) | - | Custom HTML 404 body on the fetch preset |
| [`env`](#env) | - | Node preset value passed to `fetch(request, env, ctx)` |

`main` is always `./server.js`. Oxide adds `assets` only when the project has an `index.html`. Unknown Wrangler keys fail the build instead of being silently ignored.

## preset

Use `"fetch"` for the default Node-compatible server. It serves built client files, copies `public/`, and gives hashed assets a long immutable cache lifetime.

Use `"worker"` for Cloudflare Workers. This preset writes worker configuration and leaves asset serving to the `ASSETS` binding.

```ts twoslash
import oxide from "oxidejs/vite";

oxide({
  preset: "worker",
  wrangler: { name: "my-app", compatibility_date: "2026-01-01" },
});
```

## workerEntry

The default is `src/server.ts`. When that file is present, Oxide imports it as your server. Missing the default path is fine — actions and static assets still run. An explicit path that does not exist fails at config resolve. See [Server entry](/oxide/server-entry).

```ts twoslash
import oxide from "oxidejs/vite";

oxide({ workerEntry: "src/api.ts" });
```

## outDir

The default is `dist`. Oxide writes `server.js` and any client build under this folder.

## clientDir

The default is `client`, producing `dist/client/`. It must stay inside [`outDir`](#outdir); Oxide rejects paths that escape the output folder.

## wrangler

These fields are copied into generated `wrangler.jsonc` when [`emitConfig`](#emitconfig) is enabled. `name` and `compatibility_date` are required. Oxide computes `main` and `assets`, so do not provide those keys yourself. Pass `compatibility_flags` when you need them (`nodejs_compat` is optional — celld ignores it). Cloudflare-only keys (`account_id`, `workers_dev`, `routes`, `kv_namespaces`) are emitted when you set them for wrangler deploy; **omit them for celld** — unknown top-level keys fail `celld deploy`.

## emitConfig

This defaults to `true` for `"worker"` and `false` for `"fetch"`. Set it to `false` when another tool owns the worker config.

## actions

The short form chooses a transport:

```ts twoslash
import oxide from "oxidejs/vite";

oxide({ actions: "http" }); // default
```

The object form also configures the URL path and same-origin protection:

```ts twoslash
import oxide from "oxidejs/vite";

oxide({
  actions: {
    transport: "http",
    path: "/__oxide/action",
    sameOrigin: true,
  },
});
```

- `transport` is `"http"` by default. `"ws"` uses WebSocket (`crossws` on Node/`fetch`, `WebSocketPair` on [`preset: "worker"`](#preset)).
- `path` defaults to `/__oxide/action`. It must start with `/` and cannot contain a query string.
- `sameOrigin` defaults to `true` for HTTP and WebSocket. This blocks browser calls from another site, including sibling subdomains.

On the worker preset, the generated Worker calls `server.accept()` for upgrades. Durable Object apps that need hibernation can pass a custom `accept` into `createWsHooks` (for example `ctx.acceptWebSocket(ws)`). The generated wrapper does not create a DO for you.

Turn `sameOrigin` off only when cross-origin RPC is intentional. You must then provide the appropriate authentication, CORS, and CSRF policy.

## actionHeaders

These static headers are embedded in the shared HTTP action client and are visible in browser code. Use them for public values, not private server credentials.

```ts twoslash
import oxide from "oxidejs/vite";

oxide({
  actionHeaders: { "x-client-version": "1" },
});
```

For login tokens, prefer cookies with same-origin protection or compute authorization in your own client/transport integration. Functions cannot be embedded in `actionHeaders`.

## middleware

List modules that run before server actions, your server entry, and static files in the generated production handler. Each module must default-export a function. Return a `Response` to stop the chain, or return `undefined` to continue.

```ts twoslash
// src/auth.ts
export default function auth(
  request: Request,
  context: { env: unknown; ctx: unknown }
) {
  if (!request.headers.has("authorization")) {
    return new Response("Unauthorized", { status: 401 });
  }
}
```

```ts twoslash
// vite.config.ts
import { defineConfig } from "vite";
import oxide from "oxidejs/vite";

export default defineConfig({
  plugins: [oxide({ middleware: ["./src/auth.ts"] })],
});
```

Modules run in array order, before the action gate. The second argument contains the runtime's `env` and fetch `ctx`. The same handlers are loaded through the SSR graph in development, so dev and production behave identically.

Entries can also be objects that carry their own side-effect imports — modules loaded at startup before the handler runs:

```ts twoslash
// vite.config.ts
import { defineConfig } from "vite";
import oxide from "oxidejs/vite";

export default defineConfig({
  plugins: [
    oxide({
      middleware: [
        {
          module: "@ilha/router/ssr",
          imports: ["ilha:pages/server", "ilha:loaders"],
        },
      ],
    }),
  ],
});
```

## imports

Module specifiers imported for side effects at the top of the generated server bundle — for virtual modules or integrations that self-register handlers. Also loaded once during development.

```ts twoslash
// vite.config.ts
import { defineConfig } from "vite";
import oxide from "oxidejs/vite";

export default defineConfig({
  plugins: [oxide({ imports: ["./src/register-handlers.ts"] })],
});
```

## bodyLimit

Maximum request body size in bytes on the Node preset. Larger requests receive `413 Payload Required`. Defaults to 1 MiB.

```ts twoslash
import oxide from "oxidejs/vite";

oxide({ bodyLimit: 4 * 1024 * 1024 });
```

## notFound

Custom HTML served with a 404 status when no action, user fetch, route, or asset handled the request (fetch preset). Defaults to a minimal `<h1>404 Not Found</h1>`.

```ts twoslash
import oxide from "oxidejs/vite";

oxide({ notFound: "<h1>Page not found</h1>" });
```

## env

Extra values passed as the second argument to `fetch(request, env, ctx)` on the Node preset. Read them with [`useEnv()`](/oxide/server-actions#useenv-and-usefetchctx).

```ts twoslash
import oxide from "oxidejs/vite";

oxide({ env: { API_ORIGIN: "https://api.example.com" } });
```
