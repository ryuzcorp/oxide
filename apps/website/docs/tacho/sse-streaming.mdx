A normal procedure returns one result. A streaming procedure can yield many results while it stays open. Tacho sends those values as Server-Sent Events (SSE) over the [HTTP transport](/tacho/transport/http).

## Create a stream

Use an `async function*` with `.run()`:

```ts twoslash
import { tacho } from "tacho";
import { z } from "zod";

const rpc = tacho();

export const router = rpc({
  ticks: rpc
    .input(z.object({ count: z.number() }))
    .run(async function* ({ input }) {
      for (let i = 0; i < input.count; i++) yield { value: i };
    }),
});
```

The HTTP client call resolves to an async generator. Read it with `for await`:

```ts twoslash
import { createClient } from "tacho/client/http";
import { tacho } from "tacho";
import { z } from "zod";

const rpc = tacho();
const router = rpc({
  ticks: rpc
    .input(z.object({ count: z.number() }))
    .run(async function* ({ input }) {
      for (let i = 0; i < input.count; i++) yield { value: i };
    }),
});
const client = createClient<typeof router>({
  url: "http://localhost:3000/rpc",
});
// ---cut---
const stream = await client.ticks({ count: 3 });
for await (const tick of stream) {
  console.log(tick.value);
}
```

WebSocket and batch calls reject streaming procedures. A notification returns `204` and does not start the generator.

## Fan out with `Publisher`

Use `Publisher` when one procedure publishes live updates that many stream procedures consume:

```ts twoslash
import { Publisher, tacho } from "tacho";
import { z } from "zod";

const rpc = tacho();
const events = new Publisher<{
  change: { id: string; text: string };
}>();

export const router = rpc({
  update: rpc
    .input(z.object({ id: z.string(), text: z.string() }))
    .run(({ input }) => events.publish("change", input)),
  changes: rpc.run(async function* ({ signal }) {
    for await (const change of events.subscribe("change", { signal })) {
      yield change;
    }
  }),
});
```

`publish()` delivers each payload to every current subscriber. `subscribe()` returns an ordered async generator and removes its subscription when the procedure signal aborts or the iterator closes. Use `once()` to wait for only the next payload.

A publisher lives in one process or Worker isolate. It has no replay or persistence, and each subscriber queue is unbounded. Keep publishers and subscribers in the same isolate. Use storage or an external bus when events must survive restarts or cross isolates.

## Stop and clean up

Call `return()` when you stop before the stream finishes. Tacho forwards cancellation so the server generator can run its `finally` block:

```ts twoslash
import { createClient } from "tacho/client/http";
import { tacho } from "tacho";

const rpc = tacho();
const router = rpc({
  ticks: rpc.run(async function* () {
    yield 1;
    yield 2;
  }),
});
const client = createClient<typeof router>({
  url: "http://localhost:3000/rpc",
});
// ---cut---
const stream = await client.ticks();
console.log(await stream.next());
await stream.return(undefined);
```

You can also abort with a signal:

```ts twoslash
import { createClient } from "tacho/client/http";
import { tacho } from "tacho";

const rpc = tacho();
const router = rpc({
  ticks: rpc.run(async function* () {
    yield 1;
  }),
});
const client = createClient<typeof router>({
  url: "http://localhost:3000/rpc",
});
// ---cut---
const controller = new AbortController();
const stream = await client.ticks(undefined, {
  signal: controller.signal,
});
controller.abort();
```

## Keep idle streams alive

Some proxies close quiet connections. Set `heartbeatMs` on the server handler to send SSE comment frames while no values are available:

```ts
handle(router, { heartbeatMs: 15_000 });
```

Streaming responses also set `Cache-Control: no-store` and `X-Accel-Buffering: no` so browsers and common proxies do not cache or buffer the event stream.

The client accepts both LF and standards-compliant CRLF SSE line endings.

## Network interruptions

A dropped connection ends the stream. Tacho does not retry automatically because retrying the POST would start the procedure again and could repeat database writes, emails, or other side effects.

If your app needs resume support, design stable event IDs and server-side replay storage for that specific stream. Reconnect from application code only after deciding how duplicate and missing events are handled.

## Wire format

Each yielded value is a `data:` event containing `{ jsonrpc, id, result }`. A generator return becomes `event: done`; a thrown error becomes `event: error`.
